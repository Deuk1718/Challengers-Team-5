| 영역 | 기술 | 선정 이유 |

| 프레임워크 | Next.js 14 (App Router) | SSR/SSG 지원, API Routes 내장, Vercel 배포 최적화 |

| 패키지 매니저 | npm | - |

| 배포 | Vercel | Next.js 공식 배포 플랫폼, 무료 티어 |

## 6. 핵심 데이터 스키마 (TypeScript)

```typescript
// /src/types/index.ts

export interface Skill {
  name: string;
  yearsOfExperience?: number;
}

export interface ProjectCard {
  id: string;
  techStack: string[];
  role: 'lead' | 'member' | 'solo';
  teamSize: number;
  durationMonths: number;
  url?: string;
  description?: string;
}

export interface UserProfile {
  id: string;
  name: string;
  skills: Skill[];
  experienceYears: number;
  projects: ProjectCard[];
  preferences: JobPreference;
  portfolioUrls: string[];
}

export interface JobPreference {
  levelTags: LevelTag[];
  cultureTags: string[];
  locationPreference?: string;
}

export type LevelTag = 'entry' | 'junior' | 'middle' | 'senior';

export interface CultureTag {
  id: string;
  label: string;
  rating?: number; // 재직자 평점 1~5
}

export interface FilterCondition {
  minExperienceYears?: number;
  requiredSkills: string[];
  requiredCertifications?: string[];
}

export interface JobPosting {
  id: string;
  title: string;
  company: string;
  location: string;
  employmentType: string;
  salaryRange: string;
  requiredSkills: Skill[];
  requiredExperience: { min: number; max?: number };
  levelTag: LevelTag;
  cultureTags: CultureTag[];
  mustHaveConditions: FilterCondition;
  description: string;
  postedAt: string;
}

export interface CandidateScore {
  userId: string;
  jobId: string;
  matchScore: number;           // 0~100 구직자용
  skillFitScore: number;        // 0~100 기업용
  matchedSkills: Skill[];
  missingSkills: Skill[];
  aiSimulationFeedback: string;
  levelMismatch: boolean;
}

export type FilterCategory = 'suitable' | 'review' | 'unqualified';

export interface CandidateApplication {
  id: string;
  userId: string;
  jobId: string;
  candidateScore: CandidateScore;
  filterCategory: FilterCategory;
  appliedAt: string;
}

export type ABVariant = 'A' | 'B';

export interface ABTestConfig {
  experimentId: string;
  variant: ABVariant;
}
```

## 8. API 라우트 목록

| 엔드포인트 | 메서드 | 설명 | 반환 데이터 |
|-----------|-------|------|-----------|
| `/api/recommend` | POST | 사용자 프로필 기반 공고 추천 | `JobPosting[]` + `CandidateScore[]` |
| `/api/jobs/:id/report` | GET | 역량 리포트 (합격자 평균 vs 내 프로필) | 갭 데이터, 보완 추천 |
| `/api/jobs/:id/simulate` | POST | AI 탈락 사유 시뮬레이션 | `aiSimulationFeedback: string` |
| `/api/jobs/:id/culture` | GET | 문화 태그 + 재직자 평점 | `CultureTag[]` |
| `/api/employer/filter` | POST | 지원자 자격요건 자동 필터링 | `CandidateApplication[]` (분류 포함) |
| `/api/employer/skill-fit` | POST | Skill-Fit Score 산출 | `skillFitScore`, 근거 요약 |
| `/api/ab` | POST | A/B 변형 할당 및 이벤트 로그 | `ABVariant` |

> **MVP 구현 방식**: 모든 API 라우트는 실제 DB가 아닌 Mock JSON 파일을 읽어 응답 반환

## 9. A/B 테스트 E1 설계

| 항목 | 내용 |
|-----|------|
| 실험 ID | E1 |
| 가설 | 게이지 + 스킬 배지(B) 노출 시 숫자만(A) 대비 CTR과 지원 전환율 증가 |
| A 그룹 | 매칭 점수 숫자만 표시 ("82%") |
| B 그룹 | 게이지 바 + 스킬 일치/불일치 배지 표시 |
| 구현 방법 | `userId` 해시 기반 50:50 분배, `abTest.ts` 유틸리티 함수 |
| 이벤트 | `job_card_view`, `job_card_click` 시 `ab_variant` 속성 포함 |
| MVP 범위 | 로직 + 이벤트 수집만 구현, 통계 분석은 배포 후 2주 데이터 수집 후 |

## 11. 4-Phase 개발 계획

### Phase 0: 환경 설정 및 문서화 (Day 1 전반)

**목표**: 개발 환경 완성 + 모든 문서 작성 완료

1. `/docs` 디렉토리 구조 생성 및 모든 계획/체크리스트 문서 작성
2. `npx create-next-app@latest` — Next.js 14, TypeScript, Tailwind CSS, App Router, ESLint
3. Prisma 설치: `npm install prisma @prisma/client` + `npx prisma init`
4. `schema.prisma` 작성 — UserProfile, JobPosting, ProjectCard, CandidateScore 모델
5. TypeScript 타입 정의 작성 (`/src/types/index.ts`)
6. Mock 데이터 30건 작성 (`jobs.json`, `users.json`, `candidates.json`)
7. `.env.local` + `.env.example` 환경변수 파일 준비
8. 체크리스트: `docs/checklist/phase-0-setup.md`

### Phase 1: 핵심 공고 목록 UI (Day 1 후반 ~ Day 2)

**목표**: 구직자 공고 탐색 핵심 기능 완성

1. 공통 레이아웃 — `<header>` (네비게이션), `<main>`, `<footer>` 시맨틱 구조
2. 랜딩 페이지 (`/`) — 서비스 소개, CTA
3. 공고 목록 페이지 (`/jobs`) — `<ul>` / `<li>` + `<article>` 구조
4. F-01: `JobCard.tsx` — 게이지 바 (`GaugeBar.tsx`) + 스킬 배지 (`SkillBadge.tsx`)
5. F-02: `levelTag.ts` 로직 + `LevelTag.tsx` 컴포넌트 + 레벨 필터
6. F-04: 프로필 페이지 (`/profile`) — `ProjectCardForm.tsx` (최대 5개 프로젝트 카드)
7. 공고 상세 페이지 (`/jobs/:id`) — 상세 정보 레이아웃
8. A/B 테스트 E1 로직 (`abTest.ts`) — 숫자 vs 게이지+배지 분기
9. 체크리스트: `docs/checklist/phase-1-core-ui.md`

### Phase 2: 기능 구현 (Day 3)

**목표**: 차별화 기능 완성 + 기업 대시보드

1. F-03: `CompetencyReport.tsx` — 사이드 패널, 합격자 평균 vs 내 프로필 바 차트
2. F-03: AI 탈락 사유 시뮬레이션 — Mock 응답으로 구현, `/api/jobs/:id/simulate`
3. F-05: `CultureTag.tsx` — 태그 배지 + 툴팁 평점 표시
4. F-05: 문화 태그 필터 패널 연동
5. F-06: 기업 대시보드 (`/employer`) — 지원자 3단계 분류 탭 UI
6. F-06: `SkillFitScore.tsx` + `/api/employer/skill-fit` (Mock)
7. 이벤트 트래킹 로직 (`job_card_view`, `apply_start`, `report_viewed` 등)
8. 체크리스트: `docs/checklist/phase-2-features.md`

### Phase 3: QA + 최적화 + 배포 (Day 4)

**목표**: Lighthouse ≥ 90, Vercel 배포 완료

1. Lighthouse Performance 최적화 (이미지 최적화, 번들 사이즈)
2. 접근성 검증 (키보드 네비게이션, aria-label, 색상 대비)
3. 반응형 전 구간 (360px, 768px, 1280px, 1920px) 확인
4. 에러 상태 UI (빈 상태, 로딩 상태, 에러 바운더리)
5. Vercel 배포 설정
6. 에러 발생 시 `/docs/errors/error-YYYYMMDD-{번호}.md` 작성
7. 체크리스트: `docs/checklist/phase-3-qa.md`
