# [Route: /]

## 1) 페이지 개요
- **화면명:** 랜딩
- **경로:** `/`
- **접근:** 비로그인 포함 전체 사용자
- **한 줄 설명:** 서비스 핵심 가치를 전달하고 구직자/기업 흐름을 분기하는 진입점

## 2) 페이지 목적
- CareerLog OS가 무엇인지 3초 안에 이해시킨다
- 구직자에게는 "클릭 전 적합도 확인"이라는 차별 가치를 전달한다
- 기업에게는 "자동 스크리닝 + Skill-Fit Score"라는 차별 가치를 전달한다
- 구직자 → `/jobs`, 기업 → `/employer` 두 흐름의 분기 허브 역할을 한다
- 비로그인 상태에서도 서비스 가치를 충분히 인지시켜 회원가입 전환을 유도한다

## 3) 진입 조건
- 직접 URL 입력 또는 검색 엔진을 통해 최초 진입
- 로그아웃 상태에서 서비스 접근 시
- 헤더 로고 클릭 시 (모든 페이지에서)
- 외부 공유 링크/마케팅 채널을 통한 유입

## 4) 핵심 사용자 행동
1. 서비스 슬로건과 핵심 가치를 읽고 서비스를 이해한다
2. 자신의 역할(구직자/기업)에 맞는 CTA 버튼을 클릭한다
3. 차별화 기능 3가지(매칭 스코어, AI 시뮬레이션, 문화 태그)를 훑어본다
4. 구직자/기업 양면 가치 비교 섹션에서 자신에게 해당하는 혜택을 확인한다
5. 하단 CTA에서 회원가입으로 전환한다

## 5) 레이아웃 구조 (위 → 아래)

- **섹션 A — Hero:** 슬로건 + 부제 + 구직자/기업 CTA 버튼 2개
- **섹션 B — 핵심 기능 카드 3열:** 매칭 스코어(F-01) / AI 역량 시뮬레이션(F-03) / 조직문화 핏(F-05) — 각각 아이콘 + 제목 + 1줄 설명
- **섹션 C — 데모 프리뷰:** 실제 공고 카드 목업 1장을 정적으로 표시 (게이지 바 + 스킬 배지 포함) — "이런 화면을 볼 수 있습니다"
- **섹션 D — 양면 가치 비교:** 구직자 혜택 리스트 vs 기업 혜택 리스트 — 2열 레이아웃
- **섹션 E — 숫자 지표:** "공고 30건 분석 가능", "AI 탈락 시뮬레이션", "3단계 자동 분류" 등 3개 수치 카드
- **섹션 F — 최종 CTA:** "지금 시작하세요" + 회원가입 버튼

## 7) 버튼 / 액션

- **"공고 탐색하기" (Hero 구직자 CTA)**
  - 목적: 구직자를 공고 목록으로 안내
  - 클릭 결과: `/jobs`로 이동

- **"기업 채용 시작" (Hero 기업 CTA)**
  - 목적: 기업 사용자를 대시보드로 안내
  - 클릭 결과: `/employer`로 이동 (비로그인 시 `/auth`로 우선 이동)

- **"무료로 시작하기" (최종 CTA)**
  - 목적: 회원가입 전환 유도
  - 클릭 결과: `/auth`로 이동

- **데모 카드 "지원하기" 버튼**
  - 목적: 실제 사용 경험을 미리 체험시킴
  - 클릭 결과: `/auth`로 이동 (비로그인이므로 가입 유도)

- **헤더 "로그인" 링크**
  - 목적: 기존 회원 로그인
  - 클릭 결과: `/auth`로 이동

## 8) 상태 변화 (UI 기준)

- **initial:** 모든 섹션이 정적 데이터(`landing.json`)로 즉시 렌더링. 서버 컴포넌트로 SSG 가능.
- **loading:** 이 페이지는 정적 데이터 기반이므로 로딩 상태 없음. 초기 렌더링이 곧 완성 상태.
- **success:** initial과 동일. 모든 데이터가 빌드 타임에 확정.
- **empty:** 해당 없음. 데이터가 항상 존재하는 정적 페이지.
- **error:** 해당 없음. Mock JSON 기반 정적 렌더링이므로 서버 오류 상태 불필요.

## 10) 라우터 연결 관계

- **이전에 올 수 있는 페이지:** 없음 (서비스 최초 진입점) / 모든 페이지에서 헤더 로고 클릭
- **다음으로 이동 가능한 페이지:**
  - `/jobs` — 구직자 CTA "공고 탐색하기" 클릭
  - `/employer` — 기업 CTA "기업 채용 시작" 클릭
  - `/auth` — "무료로 시작하기" 클릭 / "로그인" 클릭 / 데모 카드 "지원하기" 클릭
- **핵심 이동 이벤트:** Hero CTA 클릭이 이 페이지의 핵심 전환 지표. 구직자/기업 CTA 클릭 비율이 서비스 구조 검증의 핵심.

## 11) 설계 메모

- **이 페이지는 정적 페이지다.** 모든 데이터가 `landing.json`에서 빌드 타임에 확정되므로 SSG로 처리한다. API 호출 없음.
- **데모 카드가 핵심 차별 요소다.** 실제 공고 카드 목업(게이지 바 + 스킬 배지)을 보여줌으로써 "이 서비스가 뭘 하는지"를 글이 아닌 UI로 전달한다. `/jobs` 페이지의 카드와 시각적으로 동일해야 한다.
- **양면 시장 분기가 명확해야 한다.** 구직자/기업 CTA가 시각적으로 동등한 크기와 위치를 가져야 한다. 구직자 CTA가 primary(채움), 기업 CTA가 secondary(아웃라인).
- **비로그인 상태 전제.** 로그인 여부에 따른 분기 없음. 로그인 사용자가 `/`에 오면 동일한 랜딩을 보여준다 (대시보드 리디렉션은 이 페이지의 역할이 아님).
- **제외할 기능:** 검색 바, 로그인 폼 인라인, 공고 목록 실시간 로드, 사용자 맞춤 추천 — 이 모든 것은 `/jobs` 또는 `/profile`의 역할.

- [x] 다른 페이지를 침범하지 않았는가 — 공고 목록, 프로필, 대시보드 기능 없음
- [x] UI/UX 테스트용 목업 기준을 유지했는가 — API 호출 없는 정적 렌더링
- [x] JSON 더미 기반으로 설계되었는가 — `landing.json` 1:1 대응
- [x] 주요 행동이 3초 안에 이해되는가 — 슬로건 → CTA 2개가 첫 화면
