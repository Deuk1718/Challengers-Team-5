# [Route: /profile]

## 1) 페이지 개요
- **화면명:** 구직자 프로필
- **경로:** `/profile`
- **접근:** 로그인한 구직자 전용 (비로그인 시 `/auth`로 리디렉션)
- **한 줄 설명:** 구직자의 커리어 자산을 구조화하고 AI 역량 진단·이력서 개선 가이드를 제공하는 화면

## 2) 페이지 목적
- 구직자가 자신의 스킬·경력·프로젝트를 구조화된 형태로 등록하여 추천 알고리즘 정확도를 높인다
- 프로젝트 카드(F-04) 등록을 통해 텍스트 이력서로는 표현 불가능한 경력 복잡도를 수치화한다
- 목표 직무 기반 역량 진단(F-15)으로 "내가 시장에서 어느 수준인지"를 데이터로 보여준다
- 이력서 개선 가이드(F-16)로 모호한 표현을 탐지하고 구체적 수정 방향을 제시한다
- 전체 서비스에서 "입력 → 진단 → 개선" 순환 루프의 중심축 역할을 한다

## 3) 진입 조건
- `/onboarding` 완료 후 첫 프로필 편집을 위해 진입
- 헤더 네비게이션의 "프로필" 메뉴 클릭
- `/jobs/:id` 공고 상세에서 "프로필 보완하기" 링크 클릭
- `/mypage`에서 "프로필 수정" 버튼 클릭
- 역량 진단 결과를 다시 확인하기 위해 재방문

## 4) 핵심 사용자 행동
1. 기본 프로필 정보(이름, 스킬, 경력 연수)를 확인하고 수정한다
2. 프로젝트 카드를 등록하여 실무 경험을 구조화한다 (최대 5개)
3. 목표 직무를 선택하고 AI 역량 진단을 실행한다
4. 진단 결과에서 강점과 보완 필요 항목을 확인한다
5. 이력서 개선 가이드에서 수정 포인트와 개선 예시를 확인한다

## 5) 레이아웃 구조 (위 → 아래)

- **섹션 A — 프로필 헤더:** 사용자 이름 + 경력 레벨 태그 + 경력 연수 + "프로필 수정" 버튼
- **섹션 B — 스킬 태그 영역:** 등록된 기술 스택 태그 목록 + 경력 연수 표시 + "스킬 편집" 버튼
- **섹션 C — 프로젝트 카드 (F-04):** 등록된 프로젝트 카드 목록 (최대 5개) + "프로젝트 카드 추가" 버튼. 각 카드에 기술 스택·역할·팀 규모·기간·URL 표시
- **섹션 D — 역량 진단 결과 (F-15):** 목표 직무 선택 UI + 강점 항목 + 보완 필요 항목 2~3개 (우선순위순). 각 보완 항목에 이유 + 학습/프로젝트/이력서 3관점 보완 방향
- **섹션 E — 이력서 개선 가이드 (F-16):** 수정 포인트 목록 (원문 + 문제 설명 + 개선 예시). 하단에 "도움됨/아님" 피드백 버튼

## 7) 버튼 / 액션

- **"프로필 수정" (섹션 A)**
  - 목적: 기본 정보(이름, 경력 연수) 인라인 편집 모드 전환
  - 클릭 결과: 이름·경력 연수 필드가 편집 가능 상태로 변경, "저장"/"취소" 버튼 표시

- **"스킬 편집" (섹션 B)**
  - 목적: 기술 스택 태그 추가/삭제/경력 연수 수정
  - 클릭 결과: 스킬 영역이 편집 모드로 전환, 자동완성 태그 입력 UI 표시

- **"+ 프로젝트 카드 추가" (섹션 C)**
  - 목적: 새 프로젝트 카드 등록
  - 클릭 결과: 빈 프로젝트 카드 입력 폼 표시 (기술 스택, 역할, 팀 규모, 기간, URL)
  - 5개 등록 시 버튼 비활성화 + "최대 5개까지 등록 가능합니다" 안내

- **"저장" (프로젝트 카드 내)**
  - 목적: 프로젝트 카드 등록/수정 확정
  - 클릭 결과: 카드가 목록에 추가되고 입력 폼 닫힘

- **"삭제" (프로젝트 카드 내)**
  - 목적: 등록된 프로젝트 카드 삭제
  - 클릭 결과: 확인 다이얼로그 → 확인 시 카드 제거

- **"역량 진단 실행" (섹션 D)**
  - 목적: 목표 직무 기반 AI 역량 진단 트리거
  - 클릭 결과: 로딩 스피너 표시 → 진단 결과(강점 + 보완 항목) 렌더링

- **"이력서 개선 가이드 보기 →" (섹션 D 하단)**
  - 목적: F-15 진단 결과에서 F-16 이력서 개선 가이드로 스크롤 이동
  - 클릭 결과: 섹션 E로 스무스 스크롤

- **"도움이 됐어요 / 아니에요" (섹션 E 하단)**
  - 목적: 이력서 개선 가이드 유용성 피드백 수집
  - 클릭 결과: 선택한 버튼 하이라이트 + "피드백 감사합니다" 토스트 표시

## 8) 상태 변화 (UI 기준)

- **initial:** 프로필 헤더 + 스킬 태그 + 프로젝트 카드가 `profile.json`에서 로드되어 표시. 역량 진단 미실행 시 섹션 D에 "목표 직무를 선택하고 역량 진단을 시작하세요" 안내. 이력서 개선 가이드 미실행 시 섹션 E에 "역량 진단을 먼저 완료하세요" 안내.
- **loading:** 역량 진단 실행 중 섹션 D에 스켈레톤 UI + "AI가 역량을 분석하고 있습니다..." 메시지. 이력서 가이드 로딩 중 섹션 E에 스켈레톤 UI.
- **success:** 진단 완료 후 강점·보완 항목 표시. 이력서 가이드 로드 완료 후 수정 포인트 목록 표시. 프로젝트 카드 저장 성공 시 "저장되었습니다" 토스트.
- **empty:** 프로젝트 카드 0개일 때 "아직 등록된 프로젝트가 없습니다. 프로젝트를 추가하면 매칭 정확도가 올라갑니다." 안내 + CTA. 스킬 0개일 때 "스킬을 추가해주세요" 안내.
- **error:** 진단 실행 실패 시 "분석 중 오류가 발생했습니다. 다시 시도해주세요." + 재시도 버튼. 프로젝트 카드 저장 실패 시 인라인 에러 메시지.

## 10) 라우터 연결 관계

- **이전에 올 수 있는 페이지:**
  - `/onboarding` — 온보딩 완료 후 프로필 편집 유도
  - `/jobs/:id` — 공고 상세에서 "프로필 보완하기" 클릭
  - `/mypage` — 마이페이지에서 "프로필 수정" 클릭
  - 헤더 네비게이션 "프로필" — 모든 페이지에서 접근 가능
- **다음으로 이동 가능한 페이지:**
  - `/jobs` — 진단 완료 후 "공고 탐색하러 가기" 클릭
  - `/jobs/:id` — 역량 진단에서 추천된 공고 링크 클릭 (있을 경우)
  - `/mypage` — 헤더 네비게이션
- **핵심 이동 이벤트:** 역량 진단 완료 → 이력서 개선 가이드 확인 → 공고 탐색으로 이동하는 흐름이 이 페이지의 핵심 전환 경로

## 11) 설계 메모

- **이 페이지는 "입력 → 진단 → 개선" 순환 구조의 허브다.** 스킬·프로젝트 입력(섹션 B, C) → 역량 진단(섹션 D) → 이력서 개선(섹션 E) 순서로 위에서 아래로 자연스럽게 흐르도록 배치한다.
- **프로젝트 카드(F-04)가 추천 정확도의 핵심 변수다.** 카드 등록 여부에 따라 매칭 스코어 가중치가 달라지므로, 등록 유도 UX가 중요하다. 0개 상태에서 "프로젝트를 추가하면 매칭 정확도가 올라갑니다" 동기 부여 문구를 표시한다.
- **역량 진단(F-15)은 목표 직무 선택이 선행되어야 한다.** 목표 직무 드롭다운 선택 → "역량 진단 실행" 버튼 클릭의 2단계 구조. 온보딩에서 이미 선택한 경우 기본값으로 채워짐.
- **이력서 개선 가이드(F-16)는 역량 진단 완료 후 활성화된다.** 진단 미완료 시 비활성 상태로 "역량 진단을 먼저 완료하세요" 안내 표시. F-15 → F-16 의존 관계를 UI로 명확히 표현.
- **모든 AI 분석 결과에 "AI 분석 결과" 레이블 필수.** 역량 진단(섹션 D)과 이력서 개선 가이드(섹션 E) 모두 상단에 레이블을 표시하여 AI 추정임을 명시한다.
- **랜딩 페이지와의 차이:** 랜딩은 비로그인 정적 소개, 프로필은 로그인 후 개인 데이터 기반 동적 화면. 랜딩은 서비스 가치 전달, 프로필은 구직자 자산 구조화가 목적.
- **제외할 기능:** 지원 이력 관리(`/mypage` 역할), 공고 검색/탐색(`/jobs` 역할), 기업 관련 기능(`/employer` 역할), 이력서 파일 업로드 UI(MVP 범위 외).
