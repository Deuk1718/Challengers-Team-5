# [Route: /mypage]

## 1) 페이지 개요
- **화면명:** 마이페이지
- **경로:** `/mypage`
- **접근:** 로그인 필수 (구직자 전용)
- **한 줄 설명:** 지원 현황 추적 + 저장 공고 관리 + AI 진단 이력 열람을 한 곳에서 제공하는 구직자 개인 허브

## 2) 페이지 목적
- **존재 이유:** 구직자가 흩어진 활동 데이터(지원 내역, 저장 공고, AI 진단 결과)를 한 화면에서 확인하고 다음 행동을 결정할 수 있게 한다.
- **전체 서비스 역할:** `/jobs`에서 탐색 → `/jobs/:id`에서 지원/저장 → **`/mypage`에서 관리·추적** → `/profile`에서 보완하는 흐름의 "관리 허브" 역할. 구직자가 반복 방문하며 진행 상황을 점검하는 대시보드다.

## 3) 진입 조건
- **주요 진입 경로:**
  - GNB(글로벌 내비게이션 바)의 "마이페이지" 링크
  - 공고 상세(`/jobs/:id`)에서 지원 완료 후 "지원 현황 보기" 링크
  - 프로필(`/profile`)에서 역량 진단 완료 후 "진단 이력 보기" 링크
- **진입 상황:**
  - 지원한 공고의 현재 상태가 궁금할 때
  - 저장해둔 공고를 다시 보고 싶을 때
  - 과거 AI 진단 결과를 비교·확인하고 싶을 때

## 4) 핵심 사용자 행동
1. **지원 현황 확인** — 지원한 공고 목록과 각 공고의 진행 상태(지원완료/서류검토/면접예정/결과대기)를 확인
2. **저장 공고 재탐색** — 이전에 저장한 공고를 다시 열어보거나, 더 이상 관심 없는 공고를 삭제
3. **AI 진단 이력 열람** — 과거 역량 진단(F-15) 결과와 이력서 개선 가이드(F-16) 기록을 시간순으로 확인
4. **지원 공고로 이동** — 지원 현황이나 저장 공고에서 해당 공고 상세(`/jobs/:id`)로 바로 이동
5. **프로필 보완으로 이동** — 진단 이력에서 부족 역량을 확인하고 프로필(`/profile`)로 이동하여 보완

## 5) 레이아웃 구조 (위 → 아래)

- **섹션1: 사용자 요약 카드**
  - 이름, 목표 직무, 현재 레벨 태그, 프로필 완성도(%)
  - "프로필 수정" 버튼 → `/profile` 이동

- **섹션2: 탭 내비게이션**
  - `[지원 현황]` | `[저장 공고]` | `[AI 진단 이력]`
  - 기본 활성 탭: 지원 현황
  - 각 탭에 건수 배지 표시

- **섹션3: 탭 콘텐츠 영역**

  - **탭A — 지원 현황:**
    - 상태 필터: `전체` / `서류검토` / `면접예정` / `결과대기` / `최종결과`
    - 지원 공고 카드 리스트 (지원일 역순)
    - 각 카드: 공고 제목, 회사명, 지원일, 매칭 스코어, 진행 상태 배지

  - **탭B — 저장 공고:**
    - 저장 공고 카드 리스트 (저장일 역순)
    - 각 카드: 공고 제목, 회사명, 매칭 스코어, 저장일
    - 카드별 "삭제" 버튼, "지원하기" 버튼

  - **탭C — AI 진단 이력:**
    - 진단 결과 카드 리스트 (진단일 역순)
    - 각 카드: 진단일, 목표 직무, 강점 요약, 보완 항목 수, 이력서 개선 포인트 수
    - "상세 보기" → 해당 진단 결과 펼침

- **섹션4: 빈 상태 / 하단 CTA**
  - 각 탭 데이터가 없을 때 빈 상태 안내 + CTA 버튼

## 7) 버튼 / 액션

- **프로필 수정**
  - 목적: 프로필 페이지로 이동하여 정보 보완
  - 클릭 결과: `/profile`로 라우팅

- **탭 전환 (지원 현황 / 저장 공고 / AI 진단 이력)**
  - 목적: 탭 콘텐츠 영역 전환
  - 클릭 결과: 해당 탭 콘텐츠 표시, 활성 탭 스타일 변경

- **상태 필터 (지원 현황 탭)**
  - 목적: 특정 진행 상태의 지원 건만 필터링
  - 클릭 결과: 선택한 상태의 카드만 표시

- **공고 상세 보기**
  - 목적: 지원/저장 공고의 상세 페이지로 이동
  - 클릭 결과: `/jobs/:id`로 라우팅

- **저장 공고 삭제**
  - 목적: 관심 없는 저장 공고 제거
  - 클릭 결과: 확인 모달 → 삭제 시 리스트에서 제거 + 건수 배지 갱신

- **저장 공고에서 지원하기**
  - 목적: 저장만 해둔 공고에 바로 지원
  - 클릭 결과: `/jobs/:id`로 이동 (역량 리포트 확인 후 지원 플로우 진입)

- **AI 진단 상세 보기**
  - 목적: 과거 진단 결과 전체 확인
  - 클릭 결과: 해당 카드 아코디언 펼침 → 강점/보완 항목/이력서 개선 포인트 상세 표시

- **역량 진단 다시 하기**

  - 클릭 결과: `/profile`로 이동 (진단 섹션으로 스크롤)

## 8) 상태 변화 (UI 기준)

- **initial:** 기본 탭(지원 현황) 활성, 전체 필터 선택, 데이터 로드 완료 상태
- **loading:** 탭 전환 또는 필터 변경 시 콘텐츠 영역에 스켈레톤 UI 표시 (0.3~1초)
- **success:** 카드 리스트 정상 표시, 건수 배지 업데이트
- **empty:**
  - 지원 현황 비어있을 때: "아직 지원한 공고가 없습니다" + "공고 탐색하기" CTA

## 10) 라우터 연결 관계

- **이전에 올 수 있는 페이지:**
  - `/jobs/:id` — 지원 완료 후 "지원 현황 보기" 클릭
  - `/profile` — 역량 진단 완료 후 "진단 이력 보기" 클릭
  - GNB — 어느 페이지에서든 "마이페이지" 클릭
  - `/onboarding` — 초기 설정 완료 후 리다이렉트 가능

- **다음으로 이동 가능한 페이지:**
  - `/jobs/:id` — 지원/저장 공고 카드에서 "공고 상세 보기" 클릭
  - `/profile` — "프로필 수정", "역량 진단 다시하기" 클릭
  - `/jobs` — 빈 상태에서 "공고 탐색하기" CTA 클릭

- **핵심 이동 이벤트:**
  - 지원 현황 카드 클릭 → `/jobs/:id` (해당 공고 상세)
  - 저장 공고 "지원하기" → `/jobs/:id` (지원 플로우 진입)
  - 빈 상태 CTA → `/jobs` 또는 `/profile`

## 11) 설계 메모

- **이 페이지 설계 시 특히 중요한 점:**
  - 마이페이지는 "행동 이후의 관리"가 목적이므로, 새로운 기능을 제공하는 것이 아니라 기존 활동의 **추적·확인·재진입**에 집중해야 한다
  - 지원 상태 변화는 MVP에서는 더미 데이터로 고정 상태만 보여주되, 상태 배지 UI는 완성형으로 설계
  - 탭 간 데이터는 독립적이며, 탭 전환 시 스크롤 위치는 유지하지 않아도 된다

- **메인 페이지(`/jobs`)와의 차이점:**
  - `/jobs`는 "탐색"이 목적 → 필터·정렬·검색 중심
  - `/mypage`는 "관리"가 목적 → 상태 추적·이력 확인 중심
  - 동일한 공고 카드라도 마이페이지에서는 "매칭 스코어"보다 "진행 상태"가 더 중요한 정보

- **제외할 기능:**
  - 공고 검색/필터(레벨, 문화 태그 등) — `/jobs`의 역할
  - 프로필 편집 — `/profile`의 역할
  - 새로운 역량 진단 실행 — `/profile`의 역할 (마이페이지에서는 이력 확인만)
  - 기업 관련 기능 — `/employer`의 역할
