# [Route: /jobs]

## 1) 페이지 개요
- **화면명:** 공고 탐색
- **경로:** `/jobs`
- **접근:** 로그인/비로그인 모두 (비로그인 시 스코어 미표시)
- **한 줄 설명:** 매칭 스코어 카드 + 레벨 태그 + 문화 태그 필터로 구직자가 적합 공고를 탐색하는 핵심 화면

## 2) 페이지 목적
- 구직자가 "클릭 전에" 공고 적합도를 판단할 수 있게 한다 (F-01 매칭 스코어)
- 경력 레벨 필터로 수준 안 맞는 공고 탐색 낭비를 제거한다 (F-02 레벨 태그)
- 문화 태그 필터로 조직문화 기반 탐색을 가능하게 한다 (F-05 문화 핏)
- 구직자 플로우에서 가장 자주 방문하는 핵심 허브 화면
- A/B 테스트 E1(숫자 vs 게이지+배지)이 적용되는 실험 화면

## 3) 진입 조건
- 랜딩(`/`) "공고 탐색하기" CTA 클릭
- 헤더 네비게이션 "공고 탐색" 링크 클릭 (모든 페이지에서)
- 온보딩(`/onboarding`) 완료 후 자동 이동
- 공고 상세(`/jobs/:id`)에서 "← 목록으로" 뒤로 가기
- 마이페이지(`/mypage`)에서 "더 많은 공고 보기" 클릭

## 4) 핵심 사용자 행동
1. 공고 카드의 매칭 스코어·스킬 배지를 보고 적합도를 클릭 전에 판단한다
2. 경력 레벨 필터(신입/주니어/미들/시니어)를 선택하여 내 수준에 맞는 공고만 본다
3. 문화 태그 필터(코드 리뷰, 재택 등)를 선택하여 원하는 문화의 공고만 본다
4. 관심 공고 카드를 클릭하여 상세 페이지(`/jobs/:id`)로 이동한다
5. 카드에서 바로 "저장" 버튼을 눌러 공고를 북마크한다

## 5) 레이아웃 구조 (위 → 아래)

- **섹션 A — 페이지 헤더:** 페이지 타이틀("추천 공고") + 검색 결과 건수 + 정렬 드롭다운(최신순/스코어순)
- **섹션 B — 필터 패널:** 경력 레벨 필터 칩(F-02) + 문화 태그 필터 칩(F-05) + 필터 초기화 버튼
  - Desktop: 좌측 사이드바 (240px 고정)
  - Mobile: 상단 고정 바 + "필터" 버튼 클릭 시 바텀 시트
- **섹션 C — 공고 카드 그리드:** 매칭 스코어 카드(F-01) 반복 렌더링
  - Desktop: 3열 그리드
  - Tablet: 2열 그리드
  - Mobile: 1열 스택
- **섹션 D — 페이지네이션 / 더 보기:** "더 보기" 버튼 또는 무한 스크롤

## 7) 버튼 / 액션

- **레벨 필터 칩 (신입/주니어/미들/시니어)**
  - 목적: 경력 레벨 기준으로 공고 필터링
  - 클릭 결과: 선택 시 칩이 활성 스타일로 변경 + 카드 그리드가 필터 적용된 결과로 갱신. 중복 선택 가능(OR 조건). 재클릭 시 해제.

- **문화 태그 필터 칩 (코드 리뷰, 재택, 수평적 등)**
  - 목적: 조직문화 기준으로 공고 필터링
  - 클릭 결과: 선택 시 칩이 활성 스타일로 변경 + 해당 태그를 가진 공고만 노출. 중복 선택 가능(AND 조건).

- **"필터 초기화" 링크**
  - 목적: 모든 필터 해제
  - 클릭 결과: 모든 필터 칩 비활성 + 전체 공고 목록 복원 + 건수 원래대로

- **정렬 드롭다운 (스코어순/최신순/연봉순)**
  - 목적: 공고 카드 정렬 기준 변경
  - 클릭 결과: 드롭다운 열림 → 옵션 선택 → 카드 그리드 재정렬

- **공고 카드 전체 영역 클릭**
  - 목적: 공고 상세 페이지로 이동
  - 클릭 결과: `/jobs/:id`로 라우팅

- **카드 내 "지원하기" 버튼**
  - 목적: 빠른 지원 진입
  - 클릭 결과: `/jobs/:id`로 이동 후 역량 리포트 사이드 패널 자동 오픈

- **카드 내 "♡ 저장" 버튼**
  - 목적: 공고 북마크
  - 클릭 결과: 하트 아이콘이 채움(♥)으로 토글 + saved 상태 변경. 재클릭 시 해제.

- **"더 보기" 버튼**
  - 목적: 추가 공고 로드
  - 클릭 결과: 다음 페이지 공고 카드가 기존 목록 하단에 추가. 마지막 페이지면 버튼 숨김.

- **Mobile "필터" 버튼**
  - 목적: 모바일에서 필터 패널 접근
  - 클릭 결과: 바텀 시트로 필터 패널 올라옴 + 오버레이 표시. "적용" 클릭 시 닫힘 + 결과 갱신.

## 8) 상태 변화 (UI 기준)

- **initial:** 전체 공고 목록이 스코어 높은순으로 정렬되어 표시. 필터 미선택 상태. 건수 "추천 공고 28건" 표시.
- **loading:** 필터 변경 또는 정렬 변경 시 카드 그리드 영역에 스켈레톤 카드 6개 표시. 필터 패널은 유지.
- **filtered:** 필터 적용 후 결과 표시. 건수 갱신 "추천 공고 10건". 활성 필터 칩 강조.
- **empty:** 필터 조합에 맞는 공고가 0건일 때. 카드 그리드 영역에 아이콘 + "조건에 맞는 공고가 없습니다. 필터를 조정해보세요." + "필터 초기화" 버튼.
- **error:** JSON 로드 실패 시. "일시적인 오류가 발생했습니다." + "다시 시도" 버튼.
- **no-login:** 비로그인 상태. 카드에 매칭 스코어·스킬 배지 미표시. "로그인하면 매칭 스코어를 확인할 수 있습니다" 배너 상단 표시.

## 10) 라우터 연결 관계

- **이전에 올 수 있는 페이지:**
  - `/` — 구직자 CTA "공고 탐색하기" 클릭
  - `/onboarding` — 구직자 온보딩 완료 후
  - `/jobs/:id` — "← 목록으로" 뒤로 가기
  - `/mypage` — "더 많은 공고 보기" 클릭
  - 헤더 네비게이션 (모든 페이지)
- **다음으로 이동 가능한 페이지:**
  - `/jobs/:id` — 카드 클릭 또는 "지원하기" 버튼
  - `/auth` — 비로그인 배너 "로그인" 클릭
- **핵심 이동 이벤트:** 카드 클릭(`job_card_click`)이 이 페이지의 핵심 전환 지표. 필터 사용률과 카드 뷰→클릭 CTR이 서비스 가치 검증의 핵심.

## 11) 설계 메모

- **이 페이지는 서비스의 핵심 화면이다.** 구직자가 가장 많은 시간을 보내는 곳이며, 매칭 스코어(F-01)·레벨 태그(F-02)·문화 태그 필터(F-05) 세 가지 MVP P0/P1 기능이 동시에 작동하는 유일한 화면이다.
- **A/B 테스트 E1의 적용 대상이다.** 카드 내 스코어 표시 방식이 variant A(숫자 "82%"만)와 variant B(게이지 바 + 스킬 배지)로 분기된다. `user.abVariant` 값에 따라 카드 렌더링을 분기해야 한다.
- **필터 패널은 반응형 분기가 핵심이다.** Desktop은 좌측 사이드바 상시 표시, Mobile은 바텀 시트. 필터 상태는 동일하되 UI 컨테이너만 달라진다.
- **비로그인 상태 처리가 필요하다.** 공고 목록 자체는 볼 수 있지만, 매칭 스코어·스킬 배지는 사용자 프로필이 있어야 계산 가능하므로 비로그인 시 숨기고 로그인 유도 배너를 표시한다.
- **레벨 불일치 경고가 시각적으로 명확해야 한다.** 사용자가 주니어인데 미들/시니어 공고가 목록에 포함될 수 있다. 이때 `⚠ 레벨 불일치` 경고 배지가 레벨 태그 옆에 표시되어야 한다.
- **랜딩(`/`)과의 차이:** 랜딩은 정적 소개, 이 페이지는 동적 탐색. 랜딩의 데모 카드 1장 vs 이 페이지의 전체 카드 그리드.
- **제외할 기능:** 역량 리포트·AI 시뮬레이션(→ `/jobs/:id`), 프로젝트 카드 입력(→ `/profile`), 지원자 분류(→ `/employer`). 이 페이지에서는 "탐색과 필터링"만 한다.
