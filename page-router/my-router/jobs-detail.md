# [Route: /jobs/:id]

## 1) 페이지 개요
- **화면명:** 공고 상세
- **경로:** `/jobs/:id`
- **접근:** 로그인 구직자 (비로그인 시 기본 정보만 노출, 리포트/시뮬레이션은 로그인 유도)
- **한 줄 설명:** 특정 공고의 상세 정보를 확인하고, 역량 리포트와 AI 탈락 시뮬레이션을 통해 지원 여부를 판단하는 전환 핵심 화면

## 2) 페이지 목적
- 구직자가 공고의 전체 내용(직무 설명, 요구 스킬, 조건)을 확인하는 곳이다
- `/jobs` 목록에서 카드 클릭으로 진입한 후, **"지원할까 말까"를 결정하는 의사결정 화면**이다
- 합격자 평균 대비 내 역량 갭을 시각화(F-03 역량 리포트)하여 지원 전 객관적 판단 근거를 제공한다
- AI 탈락 사유 시뮬레이션(F-03)으로 부족한 점을 사전에 알려 "무모한 지원"을 줄이고 "보완 후 재도전" 경로를 제시한다
- 조직문화 핏 태그(F-05)를 표시하여 스킬 적합도뿐 아니라 문화적 적합성까지 판단할 수 있게 한다
- 전체 서비스 플로우에서 **탐색(Browse) → 판단(Decide) → 행동(Apply)** 중 "판단" 단계를 담당한다

## 3) 진입 조건
- `/jobs` 공고 목록 페이지에서 공고 카드 클릭 시 진입 (가장 주된 경로)
- `/mypage` 저장 공고 목록에서 저장된 공고 클릭 시 진입
- 외부 공유 링크(URL 직접 접근)로 진입
- `/profile` 역량 진단 결과에서 추천 공고 링크 클릭 시 진입

## 4) 핵심 사용자 행동
1. 공고의 상세 내용(직무 설명, 요구 스킬, 근무 조건)을 읽고 적합성을 1차 판단한다
2. "지원하기" 버튼을 클릭하여 사이드 패널에서 역량 리포트를 확인한다
3. 합격자 평균 vs 내 프로필 갭 차트를 분석하여 부족 역량을 파악한다
4. AI 탈락 시뮬레이션을 조회하여 JD 대비 부족 키워드·경험을 확인한다
5. 조직문화 핏 태그와 재직자 평점을 확인하여 문화 적합성을 판단한다
6. 최종적으로 "지원 완료" 또는 "보완 후 재도전(나중에 지원)"을 선택한다

## 5) 레이아웃 구조 (위 → 아래)

- **섹션 A — 공고 헤더:** 공고 제목, 회사명, 위치, 고용형태, 급여 범위, 경력 레벨 태그(F-02), 게시일, 저장 버튼
- **섹션 B — 매칭 요약 바:** 매칭 스코어 게이지(F-01), 일치/부족 스킬 배지, 1줄 요약 문구, 레벨 불일치 경고(F-02)
- **섹션 C — 조직문화 핏 태그:** 기업이 선택한 문화 태그 배지(F-05), 각 태그별 재직자 평점 툴팁
- **섹션 D — 직무 설명:** JD 본문 (직무 소개, 주요 업무, 자격 요건, 우대 사항, 복리후생)
- **섹션 E — 요구 스킬 상세:** 필수 스킬 목록 + 내 보유 여부 체크 표시, 우대 스킬 목록
- **섹션 F — 지원 액션 바:** "지원하기" CTA 버튼 (사이드 패널 트리거), "저장" 버튼 — 모바일에서는 하단 고정(Sticky)
- **사이드 패널 (오버레이) — 역량 리포트 + AI 시뮬레이션 (F-03):** "지원하기" 클릭 시 우측에서 슬라이드 인. 합격자 평균 vs 내 프로필 갭 바 차트, 보완 추천, AI 시뮬레이션 결과, 최종 "지원 완료" / "나중에 지원" 버튼

## 7) 버튼 / 액션

- **"지원하기" (섹션 F — Primary CTA)**
  - 목적: 역량 리포트 사이드 패널을 열어 지원 전 갭 확인을 유도
  - 클릭 결과: 우측에서 사이드 패널이 슬라이드 인되며 역량 리포트(F-03)가 표시됨. 메인 콘텐츠는 어두워짐(오버레이)

- **"저장" / "♡" (섹션 A 헤더 + 섹션 F)**
  - 목적: 관심 공고를 저장하여 나중에 다시 확인
  - 클릭 결과: 하트 아이콘이 채워짐(♡→♥), "저장되었습니다" 토스트 메시지 표시. `/mypage` 저장 공고에 추가

- **"AI 탈락 시뮬레이션 보기" (사이드 패널 내)**
  - 목적: JD 대비 부족 키워드·경험을 AI가 분석한 결과를 확인
  - 클릭 결과: 사이드 패널 하단에 AI 시뮬레이션 결과 영역이 펼쳐짐. "AI 추정 결과" 레이블 필수 표시

- **"지원 완료" (사이드 패널 내 — Primary)**
  - 목적: 최종 지원 확정
  - 클릭 결과: 지원 완료 확인 모달 표시 → "지원이 완료되었습니다" 성공 화면 → `/mypage`로 이동 가능

- **"나중에 지원" (사이드 패널 내 — Secondary)**
  - 목적: 지금은 지원하지 않고 보완 후 재도전
  - 클릭 결과: 사이드 패널 닫힘, 자동으로 공고 저장(♥) 처리, "저장되었습니다. 준비가 되면 다시 지원해보세요." 토스트 메시지

- **"뒤로가기" (헤더 좌측 화살표)**
  - 목적: 이전 페이지(공고 목록)로 복귀
  - 클릭 결과: `/jobs`로 이동 (브라우저 히스토리 back)

- **문화 태그 배지 클릭 (섹션 C)**
  - 목적: 해당 문화 태그의 재직자 평점 상세를 확인
  - 클릭 결과: 툴팁으로 평점(★) + 응답 수 표시

## 8) 상태 변화 (UI 기준)

- **initial:** URL 파라미터 `:id`로 `job-detail.json`에서 해당 공고 데이터 로드 시작. 스켈레톤 UI 표시.
- **loading:** 공고 헤더 + JD 영역에 스켈레톤 블록 표시. 매칭 스코어 영역은 게이지가 0에서 시작하는 애니메이션 준비 상태.
- **success:** 모든 데이터 렌더링 완료. 매칭 스코어 게이지가 0→82 애니메이션. 스킬 배지·문화 태그 표시. "지원하기" 버튼 활성화.
- **empty:** `:id`에 해당하는 공고가 없는 경우. "존재하지 않는 공고입니다" 메시지 + "공고 목록으로 돌아가기" 버튼.
- **error:** 데이터 로드 실패 시. "공고 정보를 불러오지 못했습니다" 메시지 + "다시 시도" 버튼.
- **side-panel-loading:** "지원하기" 클릭 후 역량 리포트 데이터 로딩 중. 사이드 패널 내 스켈레톤 바 차트 표시.
- **side-panel-no-data:** 합격자 평균 데이터 미보유 공고. "데이터 수집 중입니다. 현재 보유 정보 기준으로 간략 분석을 제공합니다." 안내 표시.

## 10) 라우터 연결 관계

- **이전에 올 수 있는 페이지:**
  - `/jobs` — 공고 카드 클릭 (가장 주된 진입 경로)
  - `/mypage` — 저장 공고 클릭
  - `/profile` — 추천 공고 링크 클릭
  - 외부 URL 직접 접근

- **다음으로 이동 가능한 페이지:**
  - `/jobs` — 뒤로가기 버튼 클릭
  - `/mypage` — 지원 완료 후 "지원 현황 보기" 이동
  - `/auth` — 비로그인 상태에서 "지원하기" 클릭 시 로그인 유도
  - `/profile` — 사이드 패널에서 "보완 후 재도전" 선택 시 역량 개선 안내 링크

- **핵심 이동 이벤트:**
  - "지원하기" 버튼 클릭 → 사이드 패널 오픈 (`apply_start` 이벤트)
  - "지원 완료" → `/mypage` 이동 (`apply_complete` 이벤트)
  - "나중에 지원" → 사이드 패널 닫힘 + 공고 자동 저장

## 11) 설계 메모

- **이 페이지의 핵심은 사이드 패널(역량 리포트)이다.** 공고 상세 자체는 여느 채용 플랫폼과 동일하지만, "지원하기" 클릭 시 열리는 역량 리포트가 CareerLog OS의 차별 가치. 사이드 패널의 완성도가 곧 이 페이지의 완성도.
- **"지원하기"가 바로 지원이 아니라 리포트 패널 트리거다.** 일반 채용 플랫폼과 달리, "지원하기" 클릭 시 바로 지원되지 않고 역량 리포트를 먼저 보여준 뒤 최종 확인("지원 완료")을 받는 2단계 플로우. 이 설계가 F-03의 핵심.
- **AI 시뮬레이션은 접힘(collapsed) 기본.** 리포트 확인 후 추가로 보고 싶은 사용자만 펼쳐보는 구조. 강제 노출하면 부정적 인상("탈락"이라는 단어)이 지원 전환율을 낮출 수 있음.
- **"AI 추정 결과" 레이블은 법적·UX적 필수 요소.** 탈락 판정이 아닌 보완 방향 중심 피드백이라는 제품 원칙을 반드시 지켜야 함.
- **모바일에서 사이드 패널은 풀스크린 모달로 전환.** 480px 패널이 모바일에서는 비현실적이므로, 전체 화면을 차지하는 바텀시트 또는 풀스크린 모달로 처리.
- **랜딩 페이지와의 차이점:** 랜딩은 정적 마케팅 페이지이고, 이 페이지는 동적 데이터(매칭 스코어, 리포트, AI 시뮬레이션)를 표시하는 인터랙티브 페이지. 로딩/에러/empty 상태가 모두 필요.
- **`/jobs` 목록 카드와의 UI 일관성:** 섹션 B의 매칭 스코어 게이지 + 스킬 배지는 `/jobs` 카드와 동일한 디자인. 사용자가 카드에서 본 정보가 상세에서도 동일하게 보여야 인지 일관성 유지.
- **제외할 기능:** 공고 수정(기업 페이지 역할), 다른 공고 추천 목록(확장 시 고려), 댓글/리뷰(v2 이후), 공유 버튼(MVP 범위 밖).
