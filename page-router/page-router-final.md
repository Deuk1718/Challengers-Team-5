### 각 화면의 역할

**1. 랜딩 (`/`)**
- 서비스 첫 인상을 결정하는 진입 화면
- 구직자/기업 양면 가치를 한눈에 전달
- 구직자 → `/jobs`, 기업 → `/employer` 분기 허브
- 비로그인 상태에서 서비스 핵심 가치(매칭 스코어, AI 시뮬레이션, 문화 태그)를 소개

**2. 공고 탐색 (`/jobs`)**
- 구직자가 가장 자주 사용하는 핵심 화면
- 매칭 스코어 게이지 + 스킬 배지로 클릭 전 적합도 판단 (F-01)
- 경력 레벨 태그 필터(F-02) + 문화 태그 필터(F-05)로 정밀 탐색
- A/B 테스트 E1 실험이 적용되는 화면 (숫자 vs 게이지+배지)

**3. 공고 상세 (`/jobs/:id`)**
- 구직자 의사결정이 발생하는 전환 핵심 화면
- 사이드 패널로 합격자 평균 vs 내 프로필 갭 시각화 (F-03)
- AI 탈락 사유 시뮬레이션으로 지원 전 부족 요소 사전 확인 (F-03)
- 문화 태그 + 재직자 평점 표시 (F-05)
- "지원하기" 또는 "보완 후 재도전" 분기

**4. 구직자 프로필 (`/profile`)**
- 구직자의 커리어 자산을 구조화하는 화면
- 프로젝트 카드 최대 5개 등록으로 추천 가중치 반영 (F-04)
- 목표 직무 기반 역량 진단 + 보완 우선순위 2~3개 제시 (F-15)
  - yeseul 기여: 강점과 부족점을 분리 표시, 보완 방향을 학습/프로젝트/이력서 3관점으로 제시
- 이력서 모호한 표현 탐지 + 개선 예시 제공 (F-16)
  - yeseul 기여: 성과 미표현·기술 나열·직무 무관 서술을 유형별로 분류하여 수정 포인트와 개선 예시를 구조적으로 제시

> **설계 참고 (yeseul 원안):** yeseul은 역량 진단(`/diagnosis`)과 이력서 개선(`/improvement`)을 각각 별도 페이지로 제안. 통합본에서는 프로필 내 섹션으로 병합하되, yeseul이 정의한 상세 흐름(목표 직무 선택 → 강점/부족점 분리 → 보완 우선순위 → 이력서 개선 가이드)을 `/profile` 내부의 단계적 UI 흐름으로 반영한다.

**5. 마이페이지 (`/mypage`)**
- 구직자 활동 이력을 한눈에 확인하는 화면
- 지원한 공고 상태 추적 (서류 접수 → 검토 중 → 결과)
- 저장한 공고 관리
- 역량 진단 이력 비교 (이전 vs 현재 진단 결과)

> **명칭 결정:** chris의 `/apply`(지원 중심)보다 deuk의 `/mypage`(지원+저장+진단 이력 포괄)가 화면의 실제 역할을 더 정확히 표현하여 채택.

**6. 초기 설정 (`/onboarding`)**
- 가입 직후 1회 진행하는 온보딩 화면
- 역할 선택: 구직자 → 목표 직무 + 스킬 + 경력 입력 / 기업 → 회사 정보 + 채용 포지션
- 구직자: 첫 역량 진단(F-15) 트리거, 추천 알고리즘 초기화
- 기업: 첫 공고 등록(F-05 문화 태그 포함) 유도

**7. 기업 대시보드 (`/employer`)**
- 기업 HR·팀장의 핵심 업무 화면
- 적합/검토필요/미충족 3단계 자동 분류 탭 (F-06)
- Skill-Fit Score 0~100점 + 근거 요약 (F-06)
- 리스크 포인트 "확인 필요" 배지 표시 (F-17)

**8. 공고 등록 (`/employer/post`)**
- 기업이 채용 공고를 작성하고 조건을 설정하는 화면
- JD 입력 + 필수 조건(최소 경력, 필수 스킬, 자격증) 설정
- 문화 핏 태그 최대 5개 선택 (F-05)
- 등록 완료 시 자격요건 자동 필터링(F-06) 활성화

**9. 지원자 상세 (`/employer/candidates/:id`)**
- 개별 지원자를 심층 검토하는 화면
- Skill-Fit Score 상세 분석 (프로젝트별 기술 매칭 근거)
- 리스크 포인트 개별 확인/완료 처리 (F-17)
  - yeseul 기여: 짧은 재직 반복, 기술 불일치, 직무 전환 이력 등 유형별 검토 신호 + 면접 확인 질문 초안 제시
- 면접 초대 / 보류 / 불합격 액션 수행

> **설계 참고 (yeseul 원안):** yeseul은 검토 필요 포인트를 `/review-signals`로 별도 분리하여 유형별(짧은 재직, 기술 불일치, 직무 전환) 검토 신호와 면접 질문 초안을 제공하는 구조를 제안. 통합본에서는 이 상세 기능을 `/employer/candidates/:id` 내의 "검토 포인트" 섹션으로 흡수하되, yeseul이 정의한 유형별 분류와 질문 초안 기능을 그대로 유지한다.

**10. 로그인/회원가입 (`/auth`)**
- 사용자 식별 및 데이터 연결
- 개인화 기능 활성화 진입점
- 가입 완료 시 `/onboarding`으로 자동 이동

────────────────────────────────

### 서비스 흐름

**구직자 흐름:**
"랜딩 진입 → 가입/로그인(`/auth`) → 온보딩(직무·스킬 설정) → 공고 탐색(매칭 스코어 확인) → 공고 상세(역량 리포트·AI 시뮬레이션) → 지원 또는 프로필 보완 → 마이페이지(결과 확인)"

**기업 흐름:**
"랜딩 진입 → 가입/로그인(`/auth`) → 온보딩(회사 정보) → 공고 등록(JD·조건·문화 태그) → 대시보드(자동 분류·Skill-Fit) → 지원자 상세(리스크 확인) → 면접 초대"
